# AI 接入页面前端规范

本规范用于生成 Web 端 AI 接入、模型选择、API Key 配置和连接测试页面。它提供稳定的页面骨架和状态行为，不要求复制某一张截图，也不把某个项目的颜色和尺寸当成固定规格。

## 设计目标

- 让用户按“服务商 → 模型 → Key 来源 → 连接测试”的顺序完成配置。
- 让当前生效的服务商、模型、Key 来源和连接状态始终可见。
- 让加载、空数据、失败和成功状态都有明确的界面反馈。
- 优先使用项目已有的 Material 3 / Material Web 标准组件，不手绘替代已有组件。
- 颜色通过项目设计令牌或 Material 角色引用；参考色只能作为初始方向。
- 页面应适配桌面浏览器，也应在较窄窗口下保持可用，不出现横向溢出。

## 页面骨架

根据项目现有架构组织组件，默认采用以下层级：

```text
AppShell
└── TopAppBar
    └── MainContent
            └── IntegrationForm
            ├── ProviderField
            ├── ModelField
            ├── ModelDiscoveryAction
            ├── TemporaryKeyField
            ├── KeyPersistenceControl
            ├── ClearTemporaryKeyAction
            ├── CurrentConnectionCard
            ├── ConnectionSourceActions
            ├── TestConnectionButton
            └── ConnectionResult
```

单页配置页面可以保留纵向顺序；如果项目已经有设置页、路由或多步表单，应复用现有导航和布局，不要为了套用此结构重构整个应用。

## 布局规则

- 页面保留安全边距，主内容使用有限最大宽度并居中；不要让所有输入框无条件铺满宽屏。
- 配置字段默认纵向排列，字段之间保留稳定间距。
- 每个字段为独立布局单元，不能让标签、输入控件、辅助文本和错误文本互相重叠。
- 字段应预留辅助文本和错误文本区域，错误出现时不能让整页大幅跳动。
- 主要连接测试动作可以使用宽按钮；清除、刷新、手动输入等辅助动作应按内容自适应。
- “使用临时 API 接入”和“使用本地 API 接入”属于同一组互斥操作，应保持同一 Row 或 Connected Button Group；窄窗口下允许改为纵向排列。
- 当前接入状态使用独立卡片或列表项承载，不把它埋在输入框辅助文本中。
- 页面不能依赖截图中的固定宽度、固定高度或绝对定位来保持布局。

## 字段结构

所有配置字段至少包含以下结构：

```text
Label
Control
Supporting text
Error text
```

服务商字段：

- 使用标准选择组件或 Exposed Dropdown。
- 选择后刷新模型候选，并保留当前服务商的历史验证模型。
- 显示服务商名称，不在用户可见区域暴露内部配置对象或 API Key。

模型字段：

- 将已验证、已发现但未验证、失败和手动输入模型区分显示。
- 模型切换后清除旧的连接结果，避免用户误以为新模型已通过测试。
- 没有模型时显示空状态和下一步操作，而不是空白下拉框。
- “其他模型 / 手动输入”必须提供输入控件，并在首次使用前执行连接测试。

模型获取：

- 提供“获取 / 刷新可用模型”按钮，作为用户主动触发的外部请求。
- 首次进入页面优先显示项目默认模型和历史验证模型；普通页面刷新不重复请求服务商。
- 服务商、Key 或 Endpoint 变化，或当前模型失效时，提示用户重新获取。
- 结果区分“服务商公开目录”“当前 Key 可用模型”和“项目默认模型”；公开目录不能直接标记为当前可用。
- 用户可以把模型加入项目默认列表、重试单个模型、查看失败原因或复制到手动输入框。
- 没有模型列表接口时，使用预置候选模型逐个测试，并明确显示这是候选探测结果。

临时 API Key 字段：

- 使用密码输入或项目现有的安全输入组件。
- 显示 Key 来源说明，但绝不回显完整 Key。
- “记住临时 API Key”默认未勾选。
- 清除动作必须同时更新输入框、当前生效来源和保存状态。

## 连接状态

连接测试和模型发现至少支持以下状态：

```text
idle       尚未测试
loading    正在请求服务商
success    连接成功
error      连接失败
empty      没有可用模型或没有测试结果
disabled   当前条件不足，暂不可操作
```

连接测试按钮在 `loading` 状态禁用并显示进度反馈，避免重复请求。测试结束后必须显示结果区域，不能只改变按钮文字。

## 当前接入卡片

当前接入区域至少展示：

```text
来源：本地 API / 临时 API
服务商：DeepSeek
模型：DeepSeek-v4.0-flash
Endpoint：api.deepseek.com
状态：未测试 / 测试中 / 可用 / 不可用
```

Endpoint 可以脱敏或只显示主机名。API Key 只显示来源和配置状态，不显示原值。

## 连接结果

连接结果使用内联结果、Snackbar 或项目已有反馈组件展示，至少包含：

- 状态图标和状态标题。
- 服务商、模型和 Key 来源。
- 用户可读的失败原因。
- 下一步操作。
- 是否允许重试。

示例：

```text
连接失败
DeepSeek / DeepSeek-v4.0-flash
API Key 无效或当前账户无权访问该模型。
建议：检查本地配置或输入新的临时 API Key。
错误类型：authentication；不可自动重试
```

错误文案必须使用统一的错误返回字段，不能只显示“请求失败”或“连接异常”。

## Material 3 Expressive 使用边界

- 优先使用项目已安装的 Material 3 / Material Web 组件。
- 使用项目的主题角色，例如 `primary`、`surface`、`surfaceContainer`、`onSurface`、`error`，不要在组件中散落硬编码颜色。
- 可以使用 Expressive 的圆角、Connected Button Group、弹性状态过渡和标准层级，但具体数值根据项目密度和视口调整。
- 输入框、按钮、选择菜单、列表项和对话框应保持统一形状系统。
- 可点击组件应有 hover、focus、pressed、disabled 状态；键盘用户必须能完成服务商选择、模型选择、Key 输入和连接测试。
- 图标只表达辅助含义，按钮仍必须包含可读文本或无障碍标签。
- 浅色和深色主题都必须检查文本、边框、错误提示和禁用态的对比度。

## 响应式和可访问性

- 桌面宽屏使用居中的主内容区域。
- 窄窗口允许按钮组换成纵向，但同一组的语义和顺序保持不变。
- 不能通过裁剪隐藏错误、辅助文本或按钮标签。
- 所有输入控件必须有可关联的 label。
- 连接结果使用可被读屏器感知的状态区域，例如 `role="status"` 或项目等价能力。
- 加载时说明正在测试哪个服务商和模型。
- 不使用颜色作为唯一的成功、失败或选中标识。

## 前端验收清单

实现后至少检查：

- 服务商切换会更新模型列表。
- 模型切换会清除旧连接结果。
- “获取 / 刷新可用模型”只在用户主动刷新、服务商或 Key 变化、模型失效时发起请求。
- 项目默认模型和历史验证模型在普通页面刷新后仍然可见。
- 临时 Key 优先于本地 Key。
- 清除临时 Key 会同步更新内存、本地保存状态和当前接入卡片。
- 连接测试包含 idle、loading、success、error 和 disabled 状态。
- 没有模型、模型发现部分失败和手动输入模型都有明确界面。
- 错误提示说明原因和下一步动作，并且不泄露 Key。
- 字段标签、输入控件、辅助文本和错误文本不重叠。
- 宽屏没有过度拉伸，窄窗口没有横向溢出。
- 浅色和深色主题都可读。
- 组件有键盘焦点、禁用态和基本读屏语义。
- 生产构建通过；按用户要求决定是否进行浏览器运行验证。
